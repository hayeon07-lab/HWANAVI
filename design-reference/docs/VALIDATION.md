# 검증 결과와 남은 실기 확인

## 통과

- JDK 17, Gradle 8.11.1, Android SDK 35 / Build Tools 35.0.0에서 `:core:test :sample:assembleDebug :sample:assembleRelease` 성공.
- 순수 Kotlin 자동 감지 엔진 JVM 테스트 **17개**, 실패/오류 0.
- 두 신호만으로 발생하지 않음, AND 후 새 안전 허가만으로 자동 시작, 안전 허가가 먼저 온 경우, 오래된/미래 신호 거부, 안전 TTL 만료, 새 위험 중단, 연결/동의/OFF 차단, 녹음 누락, 이전 token 완료 무시, 비동기 prepare 중 취소, 보류 만료, 긴 녹음의 정상 지속, 중복 신호 재사용 방지, 초기 미연결, 화면 종료, 쿨다운 중 급제동 별도 집계.
- Release APK의 테스트 UI 문자열 미포함과 Debug APK의 포함 확인.
- 3개 캐릭터 × 5개 표정 PNG 생성 및 리소스 모음 시각 확인. SVG 원본 및 Noto Sans KR OFL 동봉.
- 완성 웹의 Git HEAD와 변경 상태를 재확인: `80d2e0bef5217cdeacac53c59e826dc83df3c74b`, 작업 트리 변경 없음.

## 실행하지 않은 검증

- Pleos Connect v2.1.0 에뮬레이터/실차 설치·터치·density·포커스·차량 배포 정책.
- 실제 MP3의 Storage Access Framework 가져오기, 실제 스피커 청취, 오디오 포커스 간섭과 dB 측정, 앱 강제 종료/재부팅 후 실제 재생 확인.
- 실제 차량·음성 분석·워치 API, 시간 기준 동기화, 권한 획득, 센서 정확도와 안전 기준 검증.
- 장기 세션, background 서비스 및 프로세스 복원. 샘플은 전경 Activity 범위만 구현.

따라서 ‘APK가 빌드된다’는 것은 확인했지만 ‘실제 차량 연동이 완료됐다’는 의미가 아닙니다. 실제 어댑터와 기존 안전 판단 연결 후 아래 절차로 확인하세요.

## Android Studio / 에뮬레이터 확인 순서

1. 2560×1440 가로 에뮬레이터에서 네 메뉴와 간편 주행 UI를 확인합니다. 작은 density/큰 시스템 글꼴에서도 스크롤과 줄바꿈을 확인합니다.
2. 9개 조합마다 다른 MP3를 추가하고 각 조합에서 2개 이상을 등록·선택해 미리 듣습니다. 선택/음량/대사 변경과 앱 재실행 후 보존을 확인합니다.
3. 빈 파일·MP3가 아닌 파일·32MiB 초과 파일·파일 선택 취소·권한 취소·디코딩 오류를 확인합니다. 임의 합성/대체 음성이 나와서는 안 됩니다.
4. DEBUG에서 1개, 2개 신호와 5초 밖의 3개 신호로 이벤트가 발생하지 않는지 확인합니다. 5초 안의 AND, 안전 보류 후 안전 허가 시 자동 재생을 확인합니다.
5. prepare 중/재생 중 위험, 연결 끊김, 동의 철회, 서비스 OFF, Activity 중지, 포커스 손실로 재생이 중단되는지 확인합니다.
6. 완료 시 밝은 미소와 평온 복귀, 쿨다운, 쿨다운 이후 새 신호 필요 여부를 확인합니다.
7. LIVE에서 테스트 UI가 없고, 실제 연결/권한 없는 상태에서 감지·재생이 불가능한지 확인합니다. 기존 플레이어와 이중 재생하지 않는지도 확인합니다.
