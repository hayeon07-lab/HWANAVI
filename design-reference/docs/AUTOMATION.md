# 자동 작동 설계

## 데이터 흐름

기존 차량/음성/워치 어댑터 → ExistingSignalsSource/acceptSensor → 직렬 메인 actor → 순수 StressEngine → Play/Stop 효과 → PlaybackGateway → 상태 콜백 → EngineState → Compose UI.

실제 하드웨어 어댑터는 제공하지 않습니다. LIVE에서 연결 신호를 받지 못하면 미연결이며 자동 재생하지 않습니다. DEMO 입력은 LIVE 세션에서 거부됩니다. RELEASE sample은 developer 콘텐츠가 null이고 개발자 플래그도 false입니다.

## 이벤트 조건

- 서비스 ON + 별도 분석 동의 + 차량/음성 분석/워치 연결 + 마이크 권한이 모두 필요합니다.
- 주행 변화, 개인 기준 대비 음성 긴장 변화, 심박/HRV 변화는 각각 호스트가 판정한 `Changed` 신호입니다. UI나 이 엔진이 센서 raw 값을 분석한 것처럼 표시하지 않습니다.
- 세 종류의 신호가 예시 5초 창 안에 모두 존재해야 합니다. 동일 종류 여러 개만으로는 발생하지 않습니다. 미래/오래된/이미 소비한 타임스탬프는 거부됩니다.
- 스트레스 의심 이벤트는 진단이 아닙니다. 같은 의심 이벤트는 보류 중 재계수하지 않습니다.

## 안전·재생

- AND 충족 시 최신 안전 허가(예시 TTL 2초)가 없으면 WAITING입니다. 선택 MP3가 없으면 RECORDING_MISSING입니다. 파일/안전 정보가 도착하면 추가 사용자 조작 없이 재생을 시도합니다.
- 보류 중인 이벤트는 예시 15초 후 만료되며 나중에 안전해져도 오래된 스트레스를 재생하지 않습니다. 정상적으로 이미 재생 중인 긴 녹음은 보류 TTL 때문에 중단하지 않습니다.
- 실제 start 직전, 비동기 prepare 완료 직전 모두 `engine.permits(token)`과 `ExistingSafetyGate.isAudioSafeNow()`를 확인합니다. 새 위험 콜백은 즉시 기존 gate를 false로 하고 Hazard를 전달해야 합니다.
- 새 위험, 연결 해제, 권한/동의 철회, 서비스 OFF, 화면 중지, 안전 TTL 만료는 Play/Prepare를 중단합니다. 위험 중단한 이벤트를 자동 재개하지 않고 새 신호와 쿨다운을 기다립니다. 단순 안전 샘플 만료/일시 불허는 보류로 전환해 이벤트 유효 시간 안에서 새 안전 허가를 기다립니다.
- MediaPlayer의 실제 started 콜백 이후에만 재생 횟수를 올립니다. 시작 실패를 성공으로 집계하지 않습니다. 실패 시 재시도 루프 방지를 위해 쿨다운을 적용합니다.
- 정상 ended 후 평온 + 밝은 미소, 예시 30초 쿨다운. prepare/중단/완료에는 token을 부여해 이전 플레이어의 늦은 완료가 새 재생 상태를 바꾸지 못하게 합니다.
- 오디오 포커스 손실(duck 요청 포함)은 볼륨을 불시에 바꾸는 대신 중단합니다. focus 거부·디코딩 오류·10초 prepare 타임아웃은 실패 처리합니다.

## UI와 주행

센서 입력이 EngineState를 갱신하므로 일반 사용자는 테스트 버튼을 누를 필요가 없습니다. LIVE에서 차량이 연결되고 안전 정차가 확인되지 않으면 간편 주행 모드로 전환됩니다. 상세 메뉴는 안전 정차가 확인된 뒤 사용자가 복귀해야 열립니다. DEMO는 가상 안전 정차, PREVIEW는 비차량 UI 검토임을 각각 표시합니다.

## 범위

정책 수치는 실차 검증되지 않은 기본값이며 EnginePolicy로 조정할 수 있습니다. 안정 주행/정차/위험의 실제 판정은 기존 프로젝트가 최종 권한을 가집니다. 실제 Pleos API, 센서 ML, Bluetooth, 워치 인증, 장기 주행 이력 DB, background 서비스는 이 패키지가 구현한 기능이 아닙니다. 리포트는 현재 프로세스 세션의 진짜 이벤트만 표시하며 앱 재시작 후 누계는 복원하지 않습니다. 대사·MP3·선택·음량은 별도로 영구 저장합니다.
