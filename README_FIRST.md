# 화내비 — 기존 Android 프로젝트 + Codex Compose 디자인 통합 작업본

**원본 프로젝트를 덮어쓰지 말고 새 폴더에 압축을 해제하세요.** 2026-11-15 기준으로 사용자가 업로드한 `DaesinHwanaeCAR (2).zip`의 소스와 `HWANAEBI-Android-Compose.zip`의 UI를 통합했습니다.

## Android Studio에서 열기 (처음 하는 사람용)

1. 이 ZIP을 다운로드하여 **압축 풀기 → 새 폴더**를 만듭니다. 원래 `DaesinHwanaeCAR` 폴더에 붙여넣지 마세요.
2. Android Studio를 실행하고 **File → Open**을 클릭합니다.
3. 압축을 푼 폴더 안의 `settings.gradle.kts`가 보이는 **최상위 폴더**를 선택합니다.
4. **Trust Project**가 나오면 본인이 받은 파일임을 확인하고 선택합니다.
5. 오른쪽 위의 `Sync Project with Gradle Files`를 실행하고 완료될 때까지 기다립니다. 처음에는 인터넷 연결이 필요할 수 있습니다.
6. 에뮬레이터는 이전에 쓰던 **Medium Phone API 37.0**, 실행 구성은 **app**, 위쪽의 초록색 **▶ Run**을 누릅니다.
7. 새 디자인 화면에서 **홈 / 하루 리포트 / AI 음성팩(디자인 이름만 AI) / 설정**을 확인합니다. 작은 휴대폰 화면에서는 가로 방향으로 회전해야 잘 보일 수 있습니다.
8. 처음 실행하면 기존 `angry_voice.mp3`가 **아지매 → 순한맛**에 복사·등록됩니다. 사용자가 이미 고른 파일은 덮어쓰지 않습니다. 음성팩에서 녹음 파일을 골라 **미리 듣기**를 시험하세요.
9. 위치 정보가 필요하면 홈 아래쪽 **현재 위치·날씨 확인**을 누르고 권한을 허용합니다. 이 정보는 무료 Open-Meteo 조회에만 사용합니다.
10. **DEBUG 빌드**에서는 홈을 아래로 스크롤해 **개발자 테스트 · DEBUG 전용** 버튼을 펼쳐 **3신호 AND** 또는 **기존 급제동 / 음성 인식 시험**을 확인할 수 있습니다. **release 빌드에는 개발자 UI가 없습니다.**

**중요:** 지금 실제 차량·마이크 목소리 감정 분석·스마트워치 센서와 연결된 상태는 아닙니다. 화면의 일반 미리보기 모드는 실제 자동 재생을 하지 않습니다. 실차 주행 중 사용하지 마세요.

## 코드와 음성의 연결

- `app/.../MainActivity.kt`: 기존 파일의 급제동 시뮬레이션, 녹음 MP3 재생, 음성 인식, GPS/날씨 조회, 한국어 TTS, 로컬 리포트 저장 기능을 **삭제하지 않고 유지**. `onCreate`에서 Codex `HwanaebiRoute`에 연결.
- `app/.../HwanaebiIntegration.kt`: 기존 녹음의 안전한 기본팩 등록, **단일 디자인 MP3 플레이어를 감싸는 Gateway**, 녹음 종료 → **기존** 날씨 랜덤 대사 + **기존** TTS 이어 말하기, 위치/날씨 패널, 저장형 리포트 패널.
- `core/`: 순수 Kotlin 3신호 AND 엔진(원본 소스 그대로). **실제 센서 공급자 없음**.
- `ui/`: 디자인 화면, 15개 캐릭터 PNG, 폰트, 음성팩 파일 가져오기와 상태 관리(원본 소스·리소스 그대로).
- `app/src/debug/.../IntegratedDeveloperTools.kt`: 시뮬레이션/기존 음성 인식 시험 전용.
- `app/src/release/.../IntegratedDeveloperTools.kt`: 테스트 도구가 없는 릴리스용 구현.
- `design-reference/docs`: Codex ZIP에 포함된 원본 가이드, SVG, 폰트 라이선스.

## 음성 동작의 범위

- 첫 설치 기본 파일: 원래 `app/src/main/res/raw/angry_voice.mp3`를 앱 내부로 별도 복사하여 `ajumma_mild` 슬롯에 등록. 원본 리소스는 그대로 존재.
- 음성팩 미리 듣기: **선택한 MP3만** 재생합니다. 별도의 TTS가 붙지 않습니다.
- 개발자 3신호 AND 데모: 가상 신호 3개 충족 → 가상 안전 상태 확인 → 선택한 MP3 → 기존 짧은 날씨 대사 또는 일반 대사 **한 문장** → 고정 마무리 `화는 제가 대신 냈으니까, 이제 안전운전에 집중하세요.`
- 재생 위험 발생/서비스 종료/화면 종료 시: 디자인 엔진 Gateway의 음성 재생을 중단합니다.
- 기존 급제동 데모: 종전 3가지 시나리오를 **독립된 디버그 전체화면**에서 실행. 기존 기록은 `SharedPreferences`에 날짜별로 저장됩니다.
- 디자인 리포트의 숫자는 3신호 엔진 **현재 세션** 수치이고, 아래에 기존 시뮬레이션 **저장 기록**이 별도 표시됩니다. 두 종류의 수치를 혼합하지 않습니다.
- 앱 화면의 `AI 음성팩` 표시는 원본 **디자인 문자열만** 의미합니다. 실제 생성형 AI, OpenAI API, Python 서버, 결제는 없습니다.

## 반드시 확인할 것

- Gradle Sync 오류가 없는지, `:app:assembleDebug`를 실행했을 때 실제 빌드가 성공하는지.
- 화면에서 캐릭터 PNG/한글 폰트 표시와 음성팩 MP3 가져오기/선택/미리 듣기.
- 디자인의 3신호 가상 AND 조건(가상 신호 2개는 재생 금지; 3개+안전 확인 시 재생), 안전 보류, 새 위험 중단, 재생 완료 후 쿨다운.
- 선택 MP3 다음에 랜덤 TTS가 이어지는지. 한국어 TTS 엔진이 없는 에뮬레이터에서는 안 될 수 있습니다.
- 기존 급제동 시뮬레이션(①재생 ②시연 재생 ③안전 미확인 차단)과 리포트 기록.
- 음성 인식 시험: 에뮬레이터 마이크 입력 설정, RECORD_AUDIO 권한, Google 음성 인식 서비스가 있어야 합니다. **실제 음성 인식 성공은 이번 환경에서 검증되지 않았습니다.**
- release 빌드에 개발자 시험 버튼이 없고, 실센서 미연동 상태에서 자동 감지가 실행되지 않는지.

## 검증한 사실과 한계

- `ui/src/main` 24개, `core/src/main` 1개, `core/src/test` 1개의 **소스·자산 SHA-256이 원본 Codex ZIP과 일치**.
- 원본 `angry_voice.mp3`의 SHA-256도 그대로 보존.
- Codex 원본 3신호 엔진 Kotlin 파일을 로컬 Kotlin 컴파일러로 컴파일 완료.
- 원본 테스트 소스 17개를 오프라인 Kotlin/JUnit 호환 테스트 하네스로 실행한 결과 **17/17 통과**. (Gradle 자체 `:core:testDebugUnitTest`의 성공을 의미하지는 않습니다.)
- **Android APK 전체 빌드 및 에뮬레이터 실행: 미검증**. 검증 환경에 Android SDK 및 Gradle 9.6 배포판이 없고, Gradle 배포 사이트 DNS 접근이 차단되어 빌드를 완료할 수 없었습니다.
- Pleos Connect 에뮬레이터 및 실차 연동은 시험하지 않았으며, 현재 대상은 일반 Android 앱입니다.

## 오류가 나오면

Android Studio에서 **View → Tool Windows → Build**를 열어 빨간색 **첫 번째 오류**의 전체 내용을 캡처해 보내주세요. 기존 소스를 다시 통째로 덮어쓰지 말고 그 오류를 기준으로 수정합니다.
